# SHOPWISE Engineering Constitution

Version: 1.0

---

# Introduction

This constitution defines the immutable engineering principles for the SHOPWISE platform.

All specifications, implementation plans, architecture decisions, pull requests, and generated code MUST comply with this document.

If any document conflicts with this constitution, this constitution takes precedence.

---

# Principle I — Specification First

Every feature MUST begin with a written specification before implementation.

Required artifacts:

- Product Specification
- API Contract
- UI Contract
- Tool Contract
- Data Contract

Implementation MUST never become the source of truth.

Rationale

Documentation is the product.
Code is an implementation of the specification.

---

# Principle II — Contract First

Every interaction between components MUST be defined through explicit contracts.

Examples

- REST/OpenAPI
- JSON Schema
- Tool Protocol
- Retail SDK
- UI Protocol

Services MUST NOT depend on implementation details of other services.

---

# Principle III — AI is Stateless

The AI Runtime MUST remain stateless.

Persistent information belongs to backend services.

Examples

AI Runtime

✓ Planning

✓ Reasoning

✓ Tool Selection

✗ Session Storage

✗ Product Database

✗ Customer Database

---

# Principle IV — Backend Owns Business Logic

The backend is the source of truth for retail business capabilities.

Responsibilities include, but are not limited to:

- Product Catalog
- Inventory
- Promotions
- Customer Session
- Conversation State
- Retail Integrations
- Commerce Operations

Business logic MUST NOT be implemented inside the AI Runtime.

The AI Runtime may recommend or orchestrate actions, but execution is always delegated to backend services through defined contracts.

---

# Principle V — AI Owns Decisions

The AI Runtime is responsible for decision intelligence only.

Responsibilities include:

- Understanding user intent
- Planning
- Product recommendation
- Product comparison
- Explanation
- Tool orchestration
- Dynamic UI generation

The AI Runtime MUST NOT directly access retail business services or databases.

External AI services (such as LLM providers, embedding providers, or rerankers) are permitted.

---

# Principle VI — Tool First

The AI Runtime communicates with the backend only through Tool Protocol.

The AI MUST NOT:

- Query databases
- Call retailer APIs
- Execute SQL
- Access internal services directly

All operations MUST use registered tools.
All state-changing operations (such as cart updates, checkout preparation, or reservation) MUST be executed through backend tools.

---

# Principle VII — Retail Abstraction

All retailer integrations MUST implement the Retail SDK.

Business logic MUST never depend on a specific retailer.

Providers include

- Phong Vu
- Shopee
- Lazada
- CellphoneS

New providers MUST be added without modifying existing business logic.

---

# Principle VIII — Declarative UI

The AI MUST generate declarative UI Schema only.

The AI MUST NEVER generate

- HTML
- CSS
- React Components
- Flutter Widgets

Frontend owns rendering.

AI owns presentation intent.

---

# Principle IX — Language Responsibilities

Each language has a single responsibility.

Go

Go

- Retail APIs
- Business capabilities
- Tool execution
- Session management
- Retail provider integration

Python

- AI Runtime
- Planning
- Reasoning
- Workflow

TypeScript

- Rendering
- Interaction
- State Management

No language should duplicate responsibilities.

---

# Principle X — Simplicity for MVP

The MVP architecture consists of:

- React (Vite)
- Go Backend
- Python AI Runtime

Additional backend capabilities may be implemented by other team members, provided they expose stable contracts that conform to this constitution.

---

# Principle XI — Explainable AI

Every recommendation MUST be explainable.

Responses SHOULD include:

- Why this product
- Trade-offs
- Alternatives
- Confidence

Opaque recommendations are prohibited.

---

# Principle XII — Human-in-the-Loop Commerce

The AI assists purchasing decisions.

The AI does not make purchases autonomously.

Checkout always requires explicit user confirmation.

---

# Principle XIII — Testable Architecture

Every module MUST be independently testable.

Required testing levels:

- Unit Tests
- Contract Tests
- Integration Tests

AI workflows SHOULD include evaluation datasets.

---

# Principle XIV — Backward Compatibility

Protocols MUST be versioned.

Breaking changes require:

- New protocol version
- Migration strategy
- Compatibility documentation

---

# Principle XV — Security & Privacy

Customer data MUST be handled according to least-privilege principles.

Personally identifiable information must not be exposed to the AI Runtime unless explicitly required.

Sensitive operations require authentication and authorization.

---

# Governance

Changes to this constitution require:

- Architecture review
- Updated ADR (Architecture Decision Record)
- Version increment

This document is the highest authority within the SHOPWISE engineering repository.
